Walled DLP

A desktop app that inspects prompts and file uploads sent to ChatGPT and Perplexity, and asks you before anything sensitive leaves your machine. No browser extension.

Request path
BrowserChrome or Firefox, unmodified
→
System PACroutes only the two AI sites
→
Local HTTPS proxydecrypts, unpacks JSON, forms, multipart; OCR on files
→
ChatGPT / Perplexitygets the request only after Continue
Continue forwards the original bytesCancel returns a 403; your text stays in the box to edit

The problem

People paste contracts, customer lists and screenshots into AI chat tools. The brief was to catch a sensitive marker in prompts and in text, PDF and image uploads, ask the user through a native dialog, and recolour the AI's answers. Halfway through, the rules changed: no browser extension allowed, not even as a helper. So the inspection had to move out of the browser and onto the network.

How it works

  • Scoped interception. A local CA, name-constrained to the monitored domains, and a PAC file that sends only those hosts to the proxy. Everything else goes direct and is never decrypted.
  • Content, not endpoints. The proxy unpacks query strings, forms, multipart, nested JSON, JSON inside strings and NDJSON, so drag and drop, paste and attach are all covered.
  • Files read three ways. Plain text directly, PDFs with pypdf plus OCR on embedded images (scanned PDFs), and images with RapidOCR, including light text on dark backgrounds.
  • Background leaks handled. Analytics and typeahead requests never raise their own dialog. They follow the decision on the real prompt and are withheld otherwise.
  • Fails closed. The PAC is installed as a data: URL, so if the app stops, the sites fail to load instead of going uninspected. Unknown upload destinations are refused.
  • Answer recolouring. A style block streamed into each page as it loads, with a CSP nonce only where the site needs one.

What I found on the wire

wss://suggest.perplexity.ai {"q": "explain WALLED_SENS…"}

Perplexity sends every keystroke to its suggestion service before you press Enter. Frames carrying the marker are dropped.

POST /rest/event/analytics "queryStr": …

A copy of the question goes to analytics before the question itself, so it has to wait for your decision too.

PUT …oaiusercontent.com/files/<id>/raw

ChatGPT uploads straight to storage and retries on failure. The file name comes from the earlier create-upload request, matched by size.

MCP Guard

Approve or block every MCP tool call Claude makes, before it runs. Works with Claude Desktop and with Claude on the web.

Real MCP serversees the call only if allowed
Allow forwards the call byte for byteBlock never reaches the server; Claude gets a clear denial

The problem

MCP lets Claude write files, run commands and call APIs. Most clients only ask once per tool, if at all. MCP Guard sits inside the MCP connection itself, acting as the server to Claude and the client to the real server, so it can hold a single call, show exactly what it will do, and let you decide.

How it works

  • Transparent stdio proxy. One command rewrites Claude Desktop's config so each server runs behind the proxy. Undo restores the original entries exactly.
  • HTTP gateway for Claude Web. Supports Streamable HTTP and the older HTTP+SSE transport, reached through a tunnel because claude.ai calls connectors from Anthropic's cloud.
  • One popup per call. Simultaneous calls each get their own window and decision. Cancelling in Claude closes the popup.
  • Safe defaults. No answer in 120 s blocks the call, a dead daemon blocks every call, and the daemon API is loopback-only behind a token.

Salary Management

A web app that replaces an HR manager's shared Excel workbook for 10,000 employees across ten countries: find and edit people, record salary changes, and see how pay compares by country, department and role.

Request path
React clientMUI, TanStack Query, filters kept in the URL
→

→
Servicesbusiness rules, transactions, version checks
→
SQLiterepositories hold all SQL; WAL mode, migrations
Matching version saves the changeStale version gets a 409: "changed by someone else"

How it works

  • Money done carefully. Salaries are integer minor units with an ISO 4217 code. Amounts in different currencies are never added, averaged or compared.
  • Salary history. Every change has a reason and an effective date. Back-dated changes are allowed, and the current salary always follows the latest effective date.
  • Safe concurrent edits. Each save carries the record's version, so the second of two editors gets a clear conflict instead of silently overwriting the first.
  • Pay insights. Headcount, median and 25th/75th percentiles per country, then per department and job title within a currency, plus a salary histogram.
  • Deterministic seed. 10,000 realistic employees in under a second, identical on every run, inserted in one transaction.

What I measured

ORDER BY currency ASC, salary_minor DESC

Mixed sort directions stopped SQLite from using the (currency, salary) index. Matching them let it walk the index backwards: 1.5 ms down to 0.04 ms.

GET /api/employees?search=patel → 10 ms

Every list and insights endpoint answers in 29 ms or less (median, production build) against 10,000 employees and 26,536 history rows.
